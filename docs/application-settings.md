# 应用本地偏好

`AppSettings` 是应用配置持久化的统一入口，负责存储键、默认值、读取校验和即时写入。控件在原有交互处读取或修改偏好，无需单独的配置页面。

默认使用 Qt `QSettings` 的当前用户原生存储，组织名为 `BG5GEB`，应用名为 `GS-232B Open Control`，与既有角度预设一致。Linux 通常位于 `~/.config/BG5GEB/GS-232B Open Control.conf`（遵循 `XDG_CONFIG_HOME`）；Windows 使用当前用户注册表；macOS 使用系统偏好存储。独立工具和测试可以通过文件名构造函数使用隔离的 INI 文件。

| 偏好 | 存储键 | 默认值与校验 |
| --- | --- | --- |
| 串口号 | `connection/serialPort` | 保存时去除首尾空白；启动扫描仍能找到时恢复，否则选择扫描列表第一项；无串口时显示未找到串口，连接参数保持为空 |
| 波特率 | `connection/baudRate` | 默认 `9600`；仅支持 `1200、2400、4800、9600`，缺失或无效时回退默认值，非法参数不写入 |
| 网络连接地址 | `connection/address` | 默认 `192.168.1.50`；保存时去除首尾空白，保留 IP、主机名、端口或 WebSocket URL 的输入形式；空地址也可保存，地址有效性在连接时校验 |
| 连接模式 | `connection/networkMode` | 默认串口；布尔值校验与控制台显示一致，开启表示网络模式 |
| 控制台显示 | `view/consoleVisible` | 默认隐藏；接受布尔值及 `true`/`false`、`1`/`0`，其余值按隐藏处理 |
| 窗口基础尺寸 | `view/windowSize` | 默认 `1280×360`；保存主控制区尺寸，不含仰角区和控制台；应用退出时保存，恢复时按显示的功能区补足尺寸 |
| 窗口置顶 | `view/alwaysOnTop` | 默认关闭；布尔值校验与控制台显示一致 |
| 罗盘大圆图 | `view/greatCircleMapEnabled` | 默认关闭；布尔值校验与控制台显示一致 |
| 天线增益 | `view/antennaGain` | 默认 `0 dBi`；保存范围 `0–60 dBi`，0 表示不显示参考波瓣，数值只用于大圆图的简单主瓣宽度估算 |
| 本站网格 | `station/grid` | 默认未设置；支持 4、6、8 位 Maidenhead 网格，前两位 A–R、第三四位数字、第五六位 A–X、第七八位数字；保存时去除首尾空白并转为大写，空值清除 |
| 方位角补偿 | `rotor/azimuthOffset` | 默认 0；带符号整数度（−2147483648 至 2147483647），缺失、非整数或溢出值回退到 0 |
| 最短路径旋转 | `rotor/shortestPathEnabled` | 默认开启；接受布尔值及 `true`/`false`、`1`/`0`，缺失或无效时按开启处理 |
| 抗风模式 | `rotor/windProtectionEnabled` | 默认关闭；接受布尔值及 `true`/`false`、`1`/`0`，开启后仅在已连接且非虚拟串口透传时自动控制 |
| 抗风方位偏移 | `rotor/windDirectionOffset` | 默认 `90°`；整数范围 0–359°，目标方位为气象来风方向加此偏移 |
| 和风天气 API Host | `weather/qweatherApiHost` | 默认未设置；仅接受和风天气分配的 `*.qweatherapi.com` 专属主机名，不含协议、路径或端口 |
| 和风天气 API Key | `weather/qweatherApiKey` | 默认未设置；最多 512 个字符，与 API Host 一并保存；由 `QSettings` 本地存储，不加密 |
| 抗风天气来源 | `weather/windProvider` | 新安装默认为 `open-meteo`；选项为 `open-meteo`、`met-norway`、`qweather`。已有抗风模式开启或已有和风凭据的用户未显式选择时继续使用和风天气，避免升级后未经确认发送本站坐标 |
| 抗风来源条款确认 | `weather/windTermsAccepted` | 默认未确认；免密钥来源只有在用户阅读并确认相应条款后才会发起请求，切换来源需重新确认 |
| N1MM 接入 | `n1mm/enabled` | 默认关闭；布尔值校验与控制台显示一致，重启恢复监听；绑定失败保持关闭且不覆盖已保存偏好 |
| N1MM 旋转器名称 | `n1mm/rotorName` | 默认 `GS232B`；去除首尾空白后为 1–64 个字符，禁止逗号、`@`、制表符、换行和控制字符；缺失或无效时回退默认值 |
| GridTracker 接入 | `gridtracker/enabled` | 默认关闭；布尔值校验与控制台显示一致，重启恢复本机 UDP 12000 监听；绑定失败保持关闭且不覆盖已保存偏好 |
| WSJT-X/JTDX 接入 | `wsjtx/enabled` | 默认关闭；布尔值校验与控制台显示一致，重启恢复本机 UDP 2237 监听；绑定失败保持关闭且不覆盖已保存偏好 |
| 方位预设 | `azimuthPreset0` 至 `azimuthPreset9` | 默认 `0、45、90、135、180、225、270、315、360、405`；整数范围 0–450 度 |
| 仰角预设 | `elevationPreset0` 至 `elevationPreset5` | 默认 `0、25、50、75、100、125`；整数范围 0–180 度 |

角度预设继续使用原有键名，无需迁移；原有方位八个槽位和仰角前六个槽位的自定义值保持不变。旧的 `elevationPreset6`、`elevationPreset7` 不再读取或写入，已有值仍保留在存储中。缺失或无效的值只在读取时回退，不自动覆盖存储。读取不会创建配置文件；修改只写对应键，保留其他偏好。每次保存调用 `sync()` 并返回是否成功，界面在失败时提示用户。保留 Qt 默认的原子同步，不依赖窗口关闭或正常退出才能保存。

连接对话框的串口号、波特率、网络地址和连接模式在修改时立即保存。启动时恢复表单并自动弹出对话框，不自动连接；连接成功后关闭，主动断开或连接丢失时重新弹出。菜单栏顶层在未连接时显示“连接”，点击打开对话框；已连接时显示“断开”，点击关闭当前连接。连接过程中取消对话框会终止本次尝试，连接失败时在对话框内显示错误。虚拟串口透传连接成功后，状态栏显示外部客户端应打开的端口路径。串口不可用时的自动回退以及无串口占位项均不会在启动时覆盖原先保存的串口号，设备重新接入后仍可恢复；修改串口选择、输入或发起串口连接时保存当前串口，无端口时不因连接操作清除原选择。

设备报错摘要常驻在底部状态栏右侧，正常时显示“无报错”，故障时显示红色异常图标及“设备异常”。悬停可查看具体故障，点击打开报错详情并按需“清除报错”；详情窗口不阻挡主窗口操作，仍可随时停止旋转。断连或虚拟串口透传时显示“状态不可用”，不会将未读取的设备状态当作正常。

主页面的“手动 / 跟踪”和“长径”属于当前会话状态，每次启动为手动、长径关闭。手动模式保留本地控制及桥接应用的实测角度反馈，忽略桥接控制指令；跟踪模式允许 N1MM 和 GridTracker 控制，不重放手动期间的旧指令。长径用于本地网格、呼号/DXCC 计算及 GridTracker 的后续方位目标；数字输入、罗盘选角、方位预设、位置反馈和仰角均不受影响，N1MM 自行选择长径/短径。

方向按钮按住发送方位 `L`/`R` 或仰角 `U`/`D`，松开分别发送本轴停止 `A`/`E`；失焦、窗口隐藏、断开或切换模式也结束点动。两个六边形停止按钮均发送全轴停止 `S`。定位、停止及模式切换会取消待发的滑条命令，结束的点动不会因迟到的松键事件再次停止后续定位。

通过菜单栏“设置 → 我的网格…”编辑本站网格，无需连接设备。保存后立即生效，重启或重新打开对话框时恢复；取消不修改原值，留空保存可清除。非法网格不能保存，写入失败时对话框保留输入并提示。

通过“设置 → 方位角补偿…”输入正负整数度，无需连接设备。实际连续方位角 = 控制器角度 + 补偿值；例如补偿 −30° 后，设备 0° 对应 −30°（罗盘 330°），设备 450° 对应 420°（罗盘 60°）。保存后立即刷新读数、罗盘、数字输入范围和预设，重启后恢复；取消不改变设置，保存失败时保留对话框和输入。

通过“设置 → 方位速度”选择 X1–X4，点击后立即向设备发送对应速度命令；未连接或处于虚拟串口透传模式时禁用入口。

通过“设置 → 旋转器型号…”读取控制器已保存的型号，选择不同型号后点击“写入型号”。型号保存在控制器中；网络连接按需进行管理认证，串口连接直接写入。只有设备确认成功后才更新已保存型号；与当前生效型号不同时提示重启控制器后生效。取消不提交草稿，未连接或处于虚拟串口透传模式时禁用入口；写入超时后重新读取设备状态，避免将未确认的结果当作已保存。

“设置 → 最短路径旋转”默认开启，切换后立即生效并保存。开启时，补偿后的方位读数、数字输入及预设显示均按 360° 取余为 0–359°，负角度和多圈整数也可输入。数字、预设、罗盘及网格或呼号定位统一从 0–450° 机械行程中选择距离最近一次设备读数最近的等价位置，等距时取较小机械角度。例如无补偿时，当前机械角度 350°、目标 10° 会发送 `M370`，只顺时针转 20°；当前 10°、目标 350° 因逆时针越过 0° 不可达，仍发送 `M350`。补偿 −30° 时，输入 −30° 或 330° 都可根据当前位置发送 `M000` 或 `M360`。

关闭最短路径后，数字读数和输入恢复连续行程，范围为“补偿值”至“补偿值 + 450°”，端点均可使用，越界拒绝。例如补偿 −30° 时，输入 −30、330、420 分别发送 `M000`、`M360`、`M450`。补偿 +30° 时，范围为 30–480°，数字定位正北可输入 360°。罗盘、网格和呼号仍按圆周方位选择最近可达位置。

方位预设仍按原有 0–450° 机械角度存储，显示和右键编辑时应用补偿和最短路径模式；切换模式或更改补偿不会改写预设或迁移数据。编辑预设可输入角度、网格、呼号或 DXCC 前缀；目标方位以原机械预设为参考选择等价存储位置，回车保存但不启动旋转。取模模式下输入原显示值会保留原机械行程；点击预设时重新依据最近设备读数选解。仰角保持 0–180°，其输入、滑条和预设仍在 `W` 命令中保留原始机械方位。修改模式或补偿只更新本地界面，不启动旋转，并取消尚未提交的方位编辑和待发送的滑条命令。“设置 → 校准…”窗口中的方位和俯仰读数为只读，与主窗口接收同一设备反馈。校准方位始终显示应用补偿后的连续行程，不受最短路径开关影响；满量程调节时无需关闭最短路径。修改方位角补偿后，校准读数也立即更新。补偿基于当前界面使用的设备 P45 连续行程坐标；控制台原始命令、反馈日志及虚拟串口透传保持原协议角度。

本站网格也作为[目标方位计算](target-bearing.md)的起点：方位角输入和方位预设编辑均支持网格、呼号或 DXCC 前缀；前者回车计算并旋转，后者回车保存方位预设。呼号使用所属 DXCC 的代表坐标。

通过“视图 → 窗口置顶”让主窗口保持在其他窗口上方，默认关闭。切换后立即生效并保存，重启时恢复；切换会保留窗口的最大化状态。

通过“视图 → 大圆图”切换方位罗盘的底图，开关立即保存。开启后隐藏原罗盘的刻度，显示以本站 Maidenhead 网格几何中心为中心、正北朝上、半径 20,000 km 的等距方位投影地图；保留实测方位指针和点击选角。陆地、海洋和地图线条随当前界面主题调整，切换主题时直接沿用已下载的底图。未设置网格时，首次开启会打开“我的网格”对话框。取消或清空网格后显示设置提示，不使用旧网格的地图。

通过“设置 → 天线增益…”设置仅用于可视化参考的天线增益，单位为 dBi。增益越高，主瓣越窄；设为 0 dBi 时隐藏波瓣。波瓣只在大圆图模式且地图可用时绘制，始终沿当前实测方位指向，采用半透明填充和主题自适应高对比描边，不代表实际天线方向图或覆盖范围。

通过“设置 → 风向数据源…”选择抗风天气服务：Open-Meteo 全球模型数据（免 Key，默认）、MET Norway 全球预报（免 Key，更新较慢），或和风天气全球当前天气（需 Host 与 API Key）。免费公共 API 有各自的使用条款；选用前需阅读并确认。Open-Meteo 免费接口限非商业使用并要求署名；MET Norway 要求使用可识别的 User-Agent 并署名。免 Key 服务会通过 HTTPS 收到本站 Maidenhead 网格中心坐标和公网 IP。大陆的网络连通性需在实际网络中测试。

“模式”中的“手动”“跟踪”和“抗风”互斥。通过“设置 → 风向偏移角…”配置风向到天线目标方位的偏移；目标方位为“来风角 + 偏移角”，例如让风沿八木振子方向通过并从主梁侧向迎风，可设为 90° 或 270°。选择抗风模式后，应用以“我的网格”几何中心获取风向。Open-Meteo 和和风天气每 15 分钟轮询；MET Norway 全局至少间隔 3 小时轮询，并遵守响应中的缓存过期和验证标头，无法创建可写缓存时不会请求。MET Norway 在北欧以外的数据源约每 6 小时更新。Open-Meteo 返回全球模型风向；MET Norway 返回其最近预报时次的风向；两者不等于设备旁风速计或气象站实测。大陆坐标仅在和风天气请求中由 WGS-84 转为 GCJ-02，其他来源使用 WGS-84。目标与实测方位的最小圆周差达到 15° 时才发送旋转命令；行程选解和方位补偿沿用主控逻辑。抗风模式下不接受桥接应用的定位指令。

断开连接、虚拟串口透传、校准期间或缺少本站网格、API 凭据（和风天气）及服务条款确认时不会自动定位或请求天气。和风天气 API Key 以明文保存在当前用户设置中，并通过 HTTPS 请求头发送；只配置专用、受限的 Key。API Key 认证将在 2027 年开始实施每日请求限额，和风天气遇到 HTTP 429 后会降至 30 分钟重试；具体日期和可用额度以账户公告为准。MET Norway 全球预报在北欧以外通常约每 6 小时更新，应用最短 3 小时请求一次并按其条款设置客户端标识。当前风向数据区域显示服务来源与署名信息。

地图由 [NS6T Azimuthal Map](https://ns6t.net/azimuth/azimuth.html) 的 HTTPS 生成接口提供，首次生成会向 `ns6t.net` 发送网格中心的经纬度。请求异步进行，成功后由 Qt PDF 渲染、去掉页边空白和外侧刻度圈，以 1024×1024 PNG 原子保存到 Qt `QStandardPaths::CacheLocation` 下的 `great-circle-maps` 目录。Linux 默认通常为 `~/.cache/gs_232b_open_gui/great-circle-maps`，遵循 `XDG_CACHE_HOME`；其他平台使用 Qt 对应的用户应用缓存目录。

缓存名包含提供方、渲染版本和规范化网格，例如 `ns6t-v1-PM95AA12.png`。同一网格在重复开关、重启或切回该网格时直接离线读取；网格变化且没有对应缓存，或者缓存丢失、损坏时才请求生成，不按角度变化、重绘或窗口缩放重新请求。关闭模式或修改网格会取消旧请求，旧图不会覆盖新网格。失败时显示提示，可关闭后重新开启重试；PNG 写入失败时仍可查看当前图像，并通过状态栏提示无法离线保存。网络请求有总时限和响应大小上限，非 PDF、异常页面规格及损坏响应不会写入缓存。构建需 Qt Network 和 Qt PDF；Windows 构建脚本会补齐 `qtpdf` 模块。

新增偏好时，在 `AppSettings` 中增加明确类型的读写接口，并集中定义存储键、默认值和合法范围；使用方不直接操作 `QSettings` 或通过控件名称推导存储键。先恢复界面状态，再连接用户操作的保存逻辑，避免启动时回写默认值。持久化测试使用临时目录，验证存储契约，不固定界面布局或文字。

通过“桥接 → N1MM Logger+… → 启用”接收同机 N1MM 的旋转器命令，“配置名称…”修改名称并立即保存、生效。接入和名称的设置、通信约定与使用步骤见 [N1MM Logger+ 接入](n1mm-integration.md)。

通过“桥接 → GridTracker… → 启用”接收同机 GridTracker 的旋转器定位，并为 GridTracker 2 回复实测位置。使用 CatRotator / PstRotator 协议，配置和通信约定见 [GridTracker 接入](gridtracker-integration.md)。

通过“桥接 → WSJT-X / JTDX… → 启用”跟踪当前选中的 DX 目标。配置与报文范围见 [WSJT-X/JTDX 接入](wsjtx-integration.md)。
